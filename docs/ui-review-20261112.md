**Confirmed UI defects corrected**

1. A rejected photo-capability request left Settings checking indefinitely and caused an uncaught promise rejection. It now exits loading, explains connection/access or missing-update errors, and offers a read-only reload when appropriate.
2. Signed-image preview failures caused another uncaught rejection. They now hide the broken image and expose a retry message.
3. Failed People reads left `aria-busy=true` without a usable retry. Loading now ends, failures remain visible, and retry/automatic recovery work, including a genuinely empty result.
4. Account-save errors appeared behind an open modal. Saving/error feedback now appears inside that modal and clears when it closes.
5. Automatic capability refresh enabled invitation fields that should remain unavailable. Disabled controls now remain tied to actual reported capability.
6. A removal target could see Approve/Reject controls that the database correctly rejects. The target and requesting Admin are now excluded from those controls.
7. Retirement could submit with the required equipment radios hidden inside a closed disclosure. Invalid submission now opens the picker so native validation can reach it.
8. A valid long display name overflowed the mobile Settings layout. The heading now wraps within the existing card.

Additional recovery safeguards: an unconfirmed photo-pointer save never automatically deletes its upload or silently retries a write; the user must reload the stored state first. Offline demo photo controls now explain their unavailable state instead of retaining a checking message. The upload remains private if linking was not confirmed.
